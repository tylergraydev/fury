## Design Context

### Users
Solo developers managing AI-assisted coding workflows. They're technical, comfortable with CLI tools, and expect a desktop app that keeps pace with how fast they think and work. They use Fury as their primary interface for orchestrating AI agents (Claude, Codex) across repositories and workspaces.

### Brand Personality
**Fast, sharp, powerful.** Fury is a high-performance instrument, not a friendly assistant. It should feel like a precision tool that amplifies the developer's capabilities — aggressive where it matters, silent where it doesn't.

### Aesthetic Direction
- **Visual tone:** Dark, dense, developer-native. Pure black foundations with controlled use of blue accent and semantic colors. High information density without clutter.
- **References:** Cursor, Windsurf — AI-native code editors with clean dark UI that feels purpose-built for developers.
- **Anti-references:** No generic SaaS (rounded pastel cards, friendly illustrations), no retro terminal gimmicks (CRT effects, pixel fonts), no Electron bloat (heavy chrome, nested menus, loading spinners everywhere).
- **Theme:** Dark-mode only. Three built-in themes (Blend, Midnight, GitHub Dark) plus custom theme support via CSS variables. System font stack at 14px base.

### Emotional Goals
- **Control & confidence** — Everything is accessible, nothing is hidden. The user feels in command.
- **Speed & momentum** — Zero friction. The tool keeps up with the user, never the other way around.
- **Focus & clarity** — Clean workspace, no distractions. Information hierarchy guides attention naturally.

### Design Principles
1. **Density over decoration** — Maximize useful information per pixel. Avoid padding bloat, decorative elements, or whitespace that doesn't serve hierarchy.
2. **Instant feedback** — Every action should feel immediate. Prefer optimistic UI, subtle transitions (150ms max), and avoid loading states where possible.
3. **Keyboard-first** — Design for keyboard navigation and command palette workflows. Mouse is supported but not primary.
4. **Contrast through restraint** — Use the dark palette as a canvas. Color is reserved for status, accents, and actionable elements — never for decoration.
5. **Respect the craft** — Developers notice details. Alignment, consistent spacing, sharp borders, and predictable behavior matter more than animation or flair.

### Accessibility
- WCAG AA compliance target for contrast ratios and focus management
- Standard best practices: semantic HTML, keyboard navigation, screen reader support
- Respect `prefers-reduced-motion` where animations are used

### Technical Constraints
- Tailwind CSS 4 with CSS custom properties for theming
- Lucide icons (consistent stroke width, no mixed icon libraries)
- Monaco editor and xterm.js have their own styling — don't fight them, complement them
- Three-panel resizable layout (Sidebar | Main | RightSidebar) — components must work at variable widths
- Performance is critical: conditional rendering over hidden mounting, minimal re-renders via Zustand selectors
